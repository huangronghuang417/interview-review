回答三个问题：  
1. 聚簇索引和二级索引叶子节点分别存啥  
2. 什么场景会回表、怎么避免
3. (name, age) 联合索引，WHERE age=20 为什么用不上  
我的回答：  
1.聚簇索引的叶子节点存放完整的数据，而二级索引的叶子节点存放主键及联合索引  

2.当需要查询其他未被二级索引所覆盖的列时，需要通过主键去聚簇索引查找完整记录，这就叫回表。如何避免有点不太清楚，难道是可以通过直接查聚簇索引？  

3.因为是联合索引，所以需要name和age同时使用才能用得上，如where name='xxx' and age=20  
纠正  

1. 聚簇索引的叶子节点存放完整的数据，**二级索引叶子节点存的是：索引列的值 + 主键值。**
  
2. 当需要查询其他未被二级索引所覆盖的列时，需要通过主键去聚簇索引查找完整记录，这就叫回表。**避免回表的核心是覆盖索引——建立联合索引时把查询中需要的列都包含进去，让引擎在二级索引层就能拿到所有数据，不需要再查聚簇索引。**  
补充：索引下推（ICP，Index Condition Pushdown）能减少回表次数，但不能完全避免回表。它是把WHERE条件里索引列的判断下推到存储引擎层，过滤掉不满足的行再回表，减少IO。Extra显示Using index condition。  
3. "联合索引遵循最左前缀原则。索引 (name, age) 的B+树先按name排序，name相同再按age排序。所以 WHERE age=20 跳过了最左列name，age在全局无序，无法利用B+树的查找特性，只能全表扫描。但如果加上 name 条件，哪怕 name 是范围查询，age也能在引擎层做索引下推过滤。"  

从这三个问题可以延伸出的问题：  
1. 二级索引叶子节点存主键 → 为什么存主键不存地址？
   → 因为如果存地址，聚簇索引页分裂时地址会变，维护成本高  
2. 回表 → 什么情况下回表代价最大？
   → 回表行数多的时候（比如二级索引过滤性差，命中几万行，每行都回表 → 几万次随机IO）  
  **解释**："回表代价最大的场景是二级索引过滤性差、命中行数多的情况。因为回表本质是随机IO，每拿到一个主键值就要去聚簇索引里定位一次。如果命中几万行，就是几万次随机磁盘IO，比顺序扫描慢得多。而且如果数据不在Buffer Pool里，每次还要从磁盘加载。另外如果回表后还有额外WHERE条件过滤，大量回表是无效的，浪费IO。当回表行数超过一定比例时，优化器甚至会放弃索引走全表扫描。"
3. 覆盖索引 → 索引是不是越多越好？
   → 不是，索引占用空间、降低写性能（每次INSERT/UPDATE/DELETE都要维护索引树）  
4. 最左前缀 → 那我把所有列都放联合索引里行不行？
   → 不行，索引太大、维护成本高、索引条件下推也有局限，而且MySQL限制索引长度
